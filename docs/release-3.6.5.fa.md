# نسخهٔ ۳.۶.۵ — محصولات docs/200 و اصلاح مسیر اسکن صندوق

## محصولات

تمام **۶ فایل xlsx** در `docs/200` و زیرپوشه‌های آن خوانده شدند؛ همهٔ برگه‌های هر فایل بررسی شدند. مسیر فایل‌های آپلودشده در مخزن `docs/200` است، نه `doct`.

| مورد | تعداد |
|---|---:|
| ردیف محصول در ورودی جدید | ۶٬۰۹۶ |
| کالای جدید با شناسهٔ مستقل | ۳٬۳۸۳ |
| ردیف با بارکد از قبل دیده‌شده | ۲٬۷۱۳ |
| تعداد قبلی بانک | ۱۳٬۵۷۰ |
| تعداد نهایی بانک مشترک Android و Windows | ۱۶٬۹۵۳ |

- کالاهای جدید **بدون تصویر و با موجودی صفر** وارد می‌شوند؛ قیمت نوشته‌شده در اکسل، موجودی یا بچ خرید ایجاد نمی‌کند. برای فروش باید ورود واقعی کالا ثبت شود.
- نام فایل عکس، لینک مستقیم نیست: هیچ نام فایل تصویری در `image_url` یا گالری کالا قرار نگرفت و دانلود تصویر انجام نمی‌شود.
- نام و بارکد محصولات جدید حفظ شدند؛ صفر ابتدایی، طول بارکد یا رقم کنترلی به حدس تغییر نمی‌کند. ۷۷ کد غیرعددی منبع نیز با حروف و خط تیره حفظ شدند. این شناسه‌ها الزاماً GTIN استاندارد نیستند.
- ۱۵ ردیف فاقد بارکد، کد داخلی پایدار مبتنی بر محل و سطر منبع دریافت کردند؛ بارکد سازنده برای آن‌ها جعل نشده است.
- تطبیق محصولات دارای کد فقط با **همان بارکد** است. تشابه نام، مجوز ادغام دو کالا یا تغییر بارکد کالای قبلی نیست.
- ردیف‌های تکراری به کالای موجود اشاره می‌کنند. در ۱٬۸۳۴ مورد، نامِ ورودی با اولین نام دیده‌شده برای همان بارکد فرق داشت؛ اولین رکورد حفظ و اختلاف برای بررسی ثبت شد، نه اینکه یک بارکد به دو کالا اختصاص یابد.
- ۱۳٬۵۷۰ رکورد قبلی، از جمله تصویر و بارکدشان، در فایل بسته‌بندی‌شده عیناً حفظ شده‌اند. این انتشار اصلاح حدسی شناسه‌های قدیمی نیست.

[گزارش ردیف‌به‌ردیف و نام فایل تصاویر](CATALOG_200_REPORT.json) شامل مسیر فایل، برگه، سطر، نام کالا، بارکد و نام فایل تصویر است؛ برای اضافه کردن تصاویر در انتشار بعد قابل استفاده است. عکس خودکار از نام فایل ساخته یا از وب جست‌وجو نمی‌شود.

بازسازی و بررسی:

```sh
python scripts/build_default_catalog.py
python scripts/build_default_catalog.py --check
```

`--check` علاوه بر بررسی ساختار، مطابقت خروجی قابل بازسازی با هر دو فایل بسته‌بندی‌شده را کنترل می‌کند.

## اعمال روی نصب موجود

- Android: نشانگر بانک به `3.6.5-16953` تغییر کرده تا واردکنندهٔ مرحله‌ای بانک دوباره اجرا شود. تطبیق رشتهٔ کامل بارکد جایگزین حذف حروف/خط تیره و تطبیق نام شده است. در ادامهٔ واردکردنِ قطع‌شده، شناسهٔ کالاهای قبلاً ثبت‌شده دوباره استفاده نمی‌شود.
- Windows/backend: هنگام راه‌اندازی برنامه، هش بانک بسته‌بندی‌شده بررسی می‌شود و بانک تغییرکرده به‌صورت بدون موجودی و بدون تکثیر بارکد وارد می‌شود؛ راه‌اندازی بعدی با همان هش دوباره وارد نمی‌کند.
- قبل از هر به‌روزرسانی از اطلاعات واقعی بکاپ بگیرید. در Android اجازه دهید وارد کردن بانک در نخستین اجرای نسخهٔ جدید کامل شود؛ برنامه را حذف نکنید، APK را روی نسخهٔ قبلی نصب کنید.

## اسکن صندوق

1. **وب/ویندوز، بارکدخوان کیبوردی:** اگر اسکن با فوکوس بیرون کادر شروع می‌شد، فوکوس صندوق پس از رقم اول جابه‌جا می‌شد و رقم اول ممکن بود از مقدار کادر جا بماند. اکنون کل رشتهٔ ثبت‌شده توسط گیرندهٔ اسکن تحویل می‌شود، نه مقدار ناقص کادر. Enter اصلی متوقف و فقط یک رویداد تحویل ارسال می‌شود؛ صفرهای ابتدایی حفظ می‌شوند.
2. اسکن سخت‌افزاری در صندوق مستقیماً به مسیر تطبیق بارکد می‌رود؛ نتیجهٔ مشابهِ جست‌وجوی نام جایگزین بارکد نمی‌شود. جست‌وجوی نام همچنان جدا قابل استفاده است.
3. **وب موبایل:** اسکن صندوق قبلاً اولین نتیجهٔ جست‌وجوی مشابه را انتخاب می‌کرد؛ اکنون فقط محصول با همان رشتهٔ کامل بارکد پذیرفته می‌شود، آفلاین یا آنلاین.
4. **Android بومی:** موتور دوربین صندوق و انبار از قبل همان `ScanActivity` است و تعویض نشده است. در کادر صندوق پیشنهاد/تصحیح خودکار متن خاموش، جهت نمایش عدد مناسب شده و ثبت تکراری Enter در بالا/پایین رفتن کلید حذف شده است. تبدیل ارقام عربی و فارسی به ASCII مشترک است؛ رقم کنترلی یا طول بارکد تغییر نمی‌کند.

آزمون JavaScript خودِ handlerهای فعلی را در محیط شبیه‌سازی رویداد اجرا می‌کند: فوکوس داخل/بیرون صندوق و انبار، صفر ابتدایی، رشتهٔ طولانی، کد حروف‌دار، تحویل یکتا، تایپ آهسته و رد تطبیق ناقص. این آزمون جای آزمایش بارکدخوان فیزیکی یا دوربین گوشی را نمی‌گیرد.

## انتشار و محدودیت

APK جدید با همان کلید انتشار قبلی ساخته می‌شود. کد وب/ویندوز و شمارهٔ نسخهٔ نصب‌ساز نیز به‌روز شده‌اند. **Setup.exe جدید هنوز ساخته نشده**؛ اتصال فعلی GitHub workflow ساخت ویندوز ندارد و انتشار workflow در این اتصال قبلاً رد شده است. آزمون دوربین/بارکدخوان فیزیکی و نصب روی دستگاه واقعی در این محیط انجام نشده است؛ رفع کامل گزارش روی دستگاه کاربر نیازمند آزمون همان دستگاه است.

مولد سالانهٔ ۳.۶.۴ و ZIP آن برای حفظ صحت هش و امکان ادامهٔ اجرا، دست‌نخورده و روی همان نسخه باقی مانده‌اند؛ بانک جدید متعلق به برنامهٔ ۳.۶.۵ و سورس فعلی است.

## نتیجهٔ بررسی انتشار

مجموعهٔ کامل: **۵۱۰ آزمون موفق، ۱ مورد skip**. بررسی بازسازی بانک و آزمون رویدادهای اسکن JavaScript موفق بودند. APK نسخهٔ ۳.۶.۵ با کد ۳۰۶۰۵ ساخته و امضای آن تأیید شد؛ CSV داخل APK با بانک بک‌اند بایت‌به‌بایت یکسان است. این نتایج شامل اجرای روی گوشی یا بارکدخوان فیزیکی نیست.
