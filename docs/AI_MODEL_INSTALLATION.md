# AI MODEL INSTALLATION (v4.0)

**خلاصه:** مغز بدون مدل هم کار می‌کند (مسیر قطعی). نصب مدل محلی **اختیاری** است و سه قدم دارد:
۱) موتور `llama.cpp`  ۲) دریافت فایل مدل با تأیید sha256  ۳) فعال‌سازی در پنل مدیر.

هیچ فایل مدلی داخل مخزن گیت نیست و **نباید** باشد (`.gitignore` + سیاست انتشار).

---

## ۱. نصب موتور محلی (یک‌بار برای همیشه)

### ویندوز
1. از صفحهٔ رسمی `ggml-org/llama.cpp` نسخهٔ `llama-server.exe` را برای ویندوز دانلود کنید (build رسمی).
2. فایل را در `%LOCALAPPDATA%\SupermarketSystem\engine\` بگذارید (یا کنار `SupermarketSystem.exe`).
3. در پنل مدیر → مغز فروشگاه → مدل: اگر «موتور محلی موجود» سبز شد، همین کافی است.
4. در صورت داشتن پردازندهٔ گرافیکی، build با پشتیبانی CUDA/Vulkan سریع‌تر است، اما لازم نیست.

### لینوکس
```bash
# یا بستهٔ توزیع، یا build رسمی پروژه
which llama-server || echo "باید نصب شود"
# بررسی سریع
llama-server --version
```

> مغز مسیر باینری را از `model_manager.find_binary()` می‌گیرد و اگر پیدا نشد، صادقانه می‌گوید «موتور محلی نصب نیست» و به مسیر قطعی برمی‌گردد.

## ۲. مدل داخل نصب‌کنندهٔ ویندوز (مسیر توصیه‌شده برای فروشگاه)

از v4.0.0 نصب‌کنندهٔ ویندوز می‌تواند **مدل تأییدشده را داخل خود فایل Setup.exe** حمل کند؛
یعنی فروشگاه از همان اولین لحظه بدون اینترنت، مغز محلی دارد و هیچ دانلودی لازم نیست:

- `scripts/model/prepare_windows_installer.py` مدل را از مخزن رسمی می‌گیرد، sha256 را با
  رجیستری تطبیق می‌دهد (ناموفق = حذف فایل + شکست بیلد — مدل تأییدنشده هرگز وارد نصب‌کننده نمی‌شود)،
  فایل و `seed.json` را کنار `setup.iss` می‌گذارد و قطعهٔ `model_payload.iss` را می‌سازد.
- `setup.iss` این payload را در `%USERPROFILE%\SupermarketSystem\brain\models` نصب می‌کند
  (پوشهٔ دادهٔ کاربر، نه پوشهٔ برنامه — حذف/به‌روزرسانی برنامه، مدل را پاک نمی‌کند).
- در اولین اجرا، `ModelManager.adopt_preinstalled()` فایل را دوباره هش می‌کند، با manifest و رجیستری
  مطابقت می‌دهد، به‌صورت INSTALLED ثبت می‌کند و اگر مدلی فعال نباشد همان را فعال می‌کند.
  ناهمخوانی → ثبت UNVERIFIED + audit؛ هرگز حذف یا فعال‌سازی نمی‌شود.
- با `--engine` موتور رسمی llama.cpp (بیلد ویندوز) هم داخل نصب‌کننده قرار می‌گیرد
  (`brain/runtime/llama-server.exe`).

در بیلد محلی ویندوز `BUILD-SETUP.bat` همین مرحله را خودش اجرا می‌کند؛ اگر مدل تأیید نشود،
ساخت Setup.exe متوقف می‌شود (نسخهٔ قابل‌حمل بدون مدل ساخته می‌شود و همین را می‌گوید).
برای بیلد بدون اینترنت، فایل GGUF رسمی را دستی دانلود کنید و:
`python scripts/model/prepare_windows_installer.py --from-file <path-to-gguf>`

## ۳. دریافت مدل داخل برنامه (با تأیید هش)

### راه پیشنهادی — از داخل محصول (ویندوز/لینوکس)
پنل مدیر → مغز فروشگاه → تب **مدل** → «دریافت مدل پیشنهادی».
مسیر داخلی: `POST /api/brain/model/download` → `ModelManager.download()`.

مراحل واقعی در `ModelManager`:

```
detect → select → download → verify(sha256) → install → load → benchmark → activate
```

- دانلود در فایل موقت انجام می‌شود؛ فقط بعد از تأیید به مسیر نهایی منتقل می‌شود.
- **عدم تطابق هش:** فایل موقت **و** مقصد حذف می‌شوند، رخداد در audit ثبت می‌شود، مدل بارگذاری **نمی‌شود**.
- نبود هش در رجیستری (نسخهٔ توسعه): وضعیت `UNVERIFIED` — بارگذاری ممنوع.
- `activate` شناسهٔ نصب قبلی را در `previous_install_id` نگه می‌دارد → **rollback** ممکن است.

### راه خط فرمان (سرور بدون رابط)
```bash
python scripts/model/fetch_model.py --list                 # رجیستری + تناسب دستگاه
python scripts/model/fetch_model.py                        # مدلِ مناسب همین دستگاه
python scripts/model/fetch_model.py --model qwen2.5-1.5b-instruct-q3_k_m
python scripts/model/fetch_model.py --verify ~/.cache/brain/models/x.gguf
```

`--record` هش واقعی دانلود را در `app/services/business_brain/model_digests.json` ثبت می‌کند. این فایل فقط می‌تواند هش را با یک مقدار ۶۴ کاراکتری هگز **جایگزین** کند؛ هرگز تأیید را حذف نمی‌کند و هرگز فایل تأییدنشده را معتبر نمی‌کند.

## ۴. دسترسی اینترنت

- نیازی به اینترنت برای **کار کردن** مغز نیست؛ فقط برای **دریافت** مدل.
- روی دستگاه بدون اینترنت: فایل `.gguf` را با USB بیاورید، در مسیر مدل‌ها بگذارید و `--verify` بزنید؛ اگر هش مطابق رجیستری باشد همان فایل پذیرفته می‌شود.
- `search_web` تنها ابزاری است که به اینترنت نیاز دارد و در حالت آفلاین با خطای صریح («داده‌ای در دسترس نبود») برمی‌گردد.

## ۵. انتخاب مدل بر اساس دستگاه

| رم دستگاه | مدل پیشنهادی | حجم | context |
|---|---|---|---|
| ۴ گیگابایت | `qwen2.5-1.5b-instruct-q3_k_m` | ~۸۸۲ مگابایت | 4096 |
| ۸ گیگابایت و بیشتر | `qwen2.5-1.5b-instruct-q4_k_m` | ~۱۰۶۶ مگابایت | 4096 |

- سقف هر فایل: **۲ گیگابایت** (در رجیستری و تست اعمال شده).
- `device_profile.choose_model()` تصمیم می‌گیرد؛ روی دستگاهی که جا نمی‌شود، صریح می‌گوید `DOES NOT FIT`.
- مدل‌های ممنوع (با دلیل): `qwen3-4b-q4_k_m` (بزرگ‌تر از سقف)، `qwen3-1.7b-q8_0` (کوانتایز Q8 ممنوع)، `qwen3-1.7b-q4_k_m` (در مخزن رسمی منتشر نشده).

## ۶. پاک‌کردن و بازگشت

- «بارگذاری‌زدایی» مدل: `ModelManager.unload()` حافظه را آزاد می‌کند.
- بازگشت به نسخهٔ قبلی: با `previous_install_id` مدل قبلی دوباره فعال می‌شود.
- حذف کامل: پوشهٔ مدل‌ها را پاک کنید؛ مغز به‌صورت خودکار به مسیر قطعی برمی‌گردد و همین را در نوار وضعیت می‌گوید (نه با خطا، نه بی‌صدا).

## ۷. عیب‌یابی

| نشانه | علت محتمل | کار |
|---|---|---|
| «موتور محلی نصب نیست» | `llama-server` در PATH نیست | مسیر باینری یا `settings.manage` → مدل |
| دانلود قطع می‌شود | شبکه | دوباره بزنید؛ فایل ناقص استفاده نمی‌شود |
| «هش مطابقت ندارد» | فایل خراب/جایگزین‌شده | فایل حذف شد؛ دوباره دانلود کنید |
| پاسخ کند | دستگاه ضعیف | Q3_K_M را انتخاب کنید یا حالت قطعی |
| پاسخ قطعی می‌آید | مدل خطا داده | هشدار `MODEL_FAILED` را ببینید؛ لاگ موتور را بررسی کنید |
