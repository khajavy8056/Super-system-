# Mobile / PWA — انبارگردانی موبایل (ADR-002)

## معماری (§22, §27)
```
Mobile PWA (Add to Home Screen)
      ↓ Secure API (JWT Bearer)
Backend (FastAPI — همان سرور صندوق/فروشگاه)
      ↓
Central Database (SQLite تک‌ماشینه / قابل مهاجرت به PostgreSQL)
```
- موبایل **به همان Backend مرکزی** وصل می‌شود — هیچ دیتابیس مستقلی برای موبایل وجود ندارد؛ فقط صف آفلاین محلی که خودش «منبع حقیقت» نیست.

## نصب روی اندروید
1. گوشی و سرور در یک شبکه (LAN) یا سرور قابل‌دسترس اینترنت.
2. در Chrome اندروید: `http://<server>:8000/mobile/` → منو → **Add to Home Screen**.
3. آیکون اپ باز می‌شود (standalone، تمام‌صفحه، عمودی).

## قابلیت‌ها
- لیست جلسات انبارگردانی + ادامهٔ دقیق (progress + پرش به اولین آیتم PENDING — §20/§24).
- صفحه شمارش مطابق §24: تصویر/نام/بارکد، موجودی سیستم، ورودی موجودی واقعی، «ذخیره و بعدی».
- **ذخیره فوری هر شمارش** (§25): آنلاین → فوری به سرور؛ آفلاین → IndexedDB محلی.
- اسکن دوربین (§23) با `BarcodeDetector` بومی + اعتبارسنجی checksum GS1 سمت کلاینت؛ ورودی دستی همیشه موجود.
- همگام‌سازی خودکار با بازگشت شبکه + **تشخیص تعارض** (§26): اگر آیتم در فاصله آفلاین روی سرور تغییر/بسته شده باشد، شمارش صف‌شده به فهرست «تعارض» می‌رود و تصمیم با انسان است (ارسال مجدد / صرف‌نظر) — هرگز بی‌صدا بازنویسی نمی‌شود.

## محدودیت‌های صادقانه
| مورد | وضعیت |
|---|---|
| دوربین بارکد روی دستگاه واقعی | **تست‌نشده** (در sandbox دوربین/گوشی موجود نیست). `BarcodeDetector` در Chrome/Android موجود است؛ مرورگر بدون پشتیبانی → پیام صادقانه + ورود دستی. |
| iOS Safari | BarcodeDetector پشتیبانی نمی‌شود → ورود دستی (مستند، بدون ادعا). |
| Service Worker / نصب PWA روی دستگاه | پیاده‌شده؛ تست نصب روی گوشی واقعی انجام نشده. |
| استراتژی کش SW | فقط پوسته اپ کش می‌شود؛ `/api` هرگز کش/جعل پاسخ نمی‌شود. |
