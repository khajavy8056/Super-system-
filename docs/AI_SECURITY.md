# AI SECURITY (v4.0)

**خلاصه:** مغز یک سطح مدیریتی است، نه یک میان‌بر. هر مسیر آن پشت RBAC موجود است، هر ابزار مجوز خودش را
می‌خواهد، و هیچ عددی از مدل و هیچ نوشتنی بیرون از Action Engine پذیرفته نمی‌شود.

| موضوع | مقدار |

| پیشوند | `/api/brain/*` |
| گارد | `Depends(admin_user)` — یعنی `reports.view` **و** `settings.manage` |

| صندوق‌دار/فروشنده | **403 روی همهٔ مسیرها** |

تا صندوق‌دار به داده مالی مدیر نرسد.

## ۲. جدول دسترسی ابزارها

| گروه ابزار | مجوز | صندوق‌دار |
|---|---|---|
| سیاست‌ها، تصمیم‌ها، پیگیری‌ها، فکت‌ها، کمپین‌ها، سخت‌افزار | `settings.manage` | ❌ `ToolDenied` |
| نقد، چک، مطالبات پرداختنی، هزینه‌ها، تأمین‌کننده | `accounting.view` | ❌ `ToolDenied` |
| موجودی، انقضا، کمبود | `inventory.view` | ✅ (بی‌خطر) |
| فروش، سود | `reports.view` | ✅ (همان دسترسی گزارش فعلی) |

وقتی ابزاری رد می‌شود:
۱) رکورد `ToolCall` ثبت می‌شود، ۲) `ToolDenied` بالا می‌آید، ۳) تلاش در `ctx.trace` می‌ماند،
۴) `ctx.known_numbers()` خالی می‌ماند — یعنی مدل نه به داده رسید و نه عددی برای گفتن دارد.

## ۳. مسیر نوشتن

```
LLM (پیشنهاد) → Action Proposal → Policy → Permission → insight_actions.execute_actions
              → VALIDATE → SAVEPOINT → EXECUTE → VERIFY → COMMIT → audit
```

- **پرداخت، انتقال وجه، حذف**: همیشه `HIGH_RISK`، همیشه نیازمند تأیید انسانی؛ هیچ مسیر خودکاری وجود ندارد.
- **پیامک، تغییر قیمت، کمپین، سفارش خرید**: `APPROVAL` — مدل می‌تواند پیشنهاد بدهد، اجرا فقط با تأیید مدیر.
- پیش از تأیید، `execution.executions == []` — تست‌شده.
- نوشتن مستقیم از LLM ممنوع است: تنها ابزارهای نوشتنی قابل فراخوانی، همان ۵ مورد کم‌خطر
  (`set_policy`, `create_task`, `create_followup`, `record_memory_fact`, `measure_action`) هستند
  و هیچ‌کدام پول، قیمت یا پیامک را تغییر نمی‌دهد.

## ۴. عدد جعلی

`grounding.py` هر عدد پاسخ را با `ctx.known_numbers()` مقایسه می‌کند. عدد بی‌منبع حذف می‌شود و
`warnings=[NUMBER_REJECTED]` ثبت می‌گردد. سود، حاشیه، نقدینگی، بدهی، مطالبات، پیش‌بینی و اقتصاد تخفیف
فقط از سرویس‌های قطعی v3.x می‌آیند و هرگز از متن مدل.

## ۵. حریم خصوصی

- حالت پیش‌فرض: **فقط محلی**. `allow_cloud_ai = False` و `ai_mode = "local_only"`.
- حالت‌های انتخابی صاحب فروشگاه: `local_only` / `local_preferred` / `cloud_fallback` / `cloud_only`.
- بدون نیاز و بدون رضایت، این داده‌ها از دستگاه خارج نمی‌شوند: شمارهٔ تماس مشتری، آدرس،
  هویت مشتری، سوابق مالی، اطلاعات خصوصی تأمین‌کننده و حساب‌های مالی.
- `send_sms` نیازمند تأیید است و متن پیامک قبل از ارسال به مدیر نشان داده می‌شود.

## ۶. مقاوم‌سازی مدل

- دستیار فقط tool می‌سازد؛ حتی اگر مدل «SQL» بنویسد، ابزاری برای اجرای آن وجود ندارد.
- حداکثر ۸ دور ابزار؛ در دور آخر ابزارها خاموش می‌شوند.
- متن استدلال، JSON خام و فراخوانی‌های ابزار **هرگز** به مدیر نمایش داده نمی‌شوند (`clean_answer`).
- فایل مدل با sha256 تأیید می‌شود؛ عدم تطابق → حذف فایل + audit + عدم بارگذاری.
- منبع مدل فقط مخزن رسمی Qwen؛ آینهٔ ناشناس ممنوع. مدل‌های ممنوع با دلیل ثبت شده‌اند.

## ۷. کیفیت داده به‌عنوان مرز امنیتی

اگر داده ناقص/متناقض باشد، پرچم `DATA_QUALITY_BLOCKED` بالا می‌رود، اطمینان تصمیم `blocked` می‌شود و
تصمیم مالی قطعی صادر **نمی‌شود**. سیستم به‌جای حدس زدن، دربارهٔ دادهٔ خودش هشدار می‌دهد.
