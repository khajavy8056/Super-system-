# AI MEMORY (v4.0)

**اصل:** «یادگیری» در این سیستم یعنی **حافظهٔ ساختاریافته + اندازه‌گیری واقعی**، نه تغییر وزن مدل.
هیچ fine-tuning روی دستگاه انجام نمی‌شود و هیچ «یادگیری» جعلی گزارش نمی‌شود.

---

## ۱. پنج حافظه

| حافظه | جدول | چیست | چطور پر می‌شود |
|---|---|---|---|
| گفت‌وگو | `brain_messages` | پیام‌های مدیر و پاسخ‌ها + موجودیت‌های حل‌شده | هر `/brain/chat` |
| کسب‌وکار | `brain_memory_facts` | فکت‌های پایدار («تأمین‌کنندهٔ X اولویت دارد») | `record_memory_fact` |
| سیاست | `brain_policies` | قواعد صریح صاحب فروشگاه | `set_policy` / پنل سیاست‌ها |
| پروفایل فروشگاه | `store_profile.py` (روی دادهٔ واقعی) | اندازه، ساعات اوج، دسته‌های غالب، رفتار پرداخت | محاسبه از دیتابیس |
| تصمیم | `brain_decisions` | تصمیم، دلیل، گزینه‌ها، تأیید، نتیجه، پیامد | `decisions.py` |

به‌علاوه **موتور پیگیری** (`brain_followups`) زمان‌بندی اندازه‌گیری را نگه می‌دارد.

---

## ۲. سیاست‌های پیش‌فرض (ساختاریافته)

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `max_discount_without_approval` | 15 | تخفیف بیش از این درصد بدون تأیید مدیر ممنوع |
| `maximum_discount_any` | 40 | سقف مطلق تخفیف |
| `minimum_cash_reserve` | 0 | کف نقدینگی که نباید شکسته شود |
| `minimum_margin_pct` | 3 | حد سود قابل قبول |
| `require_approval_for_sms` | True | پیامک همیشه تأیید می‌خواهد |
| `require_approval_for_price` | True | تغییر قیمت همیشه تأیید می‌خواهد |
| `expiry_action_horizon_days` | 14 | افق هشدار انقضا |
| `max_active_alerts` | 5 | سقف کارت‌های همزمان (ضد اسپم) |
| `allow_cloud_ai` | False | ابر ممنوع تا وقتی صاحب فروشگاه اجازه دهد |
| `ai_mode` | `local_only` | فقط محلی |

اثر واقعی: در سناریوی «صندوق ۱۸۰ میلیون، چک فردا ۱۲۰ میلیون»، اگر سیاست سقف تخفیف را ۰ بگذارد،
گزینهٔ تخفیف‌محور از `policy_verdict` رد می‌شود و گزینهٔ وصول مطالبات می‌ماند.

## ۳. حافظهٔ تصمیم — ساختار کامل

```
decision_id  →  problem  →  evidence[]  →  options[]  →  selected  →  reason
             →  approval{state, by, at}  →  action{type, payload}
             →  result{}  →  measurement{metric, window_days, baseline, success_rule}
             →  outcome
```

### پیامدها (outcome)

| مقدار | معنی | شرط |
|---|---|---|
| `POSITIVE` | بهتر از پایه | معیار واقعاً بهبود داشته |
| `NEUTRAL` | تغییری نداشته | داخل بازهٔ نوسان |
| `NEGATIVE` | بدتر شده | افت واقعی |
| `INSUFFICIENT` | دادهٔ کافی نبود | کمتر از حد لازم مشاهده |
| `NOT_MEASURABLE` | معیار قابل اندازه‌گیری نیست | در `MEASUREMENT_SPECS` نبود |

**قاعدهٔ سخت:** `INSUFFICIENT` هرگز به `POSITIVE` تبدیل نمی‌شود. اگر داده نبود، همان گفته می‌شود.

## ۴. قرارداد اندازه‌گیری

هر تصمیم اجراشده یک قرارداد دارد:

```json
{"metric": "receivables_collected", "window_days": 14,
 "baseline": {"days": 14, "value": 46_000_000},
 "success_rule": "بهبود ≥ ۱۰٪ نسبت به بازهٔ پایه"}
```

۱۰ معیار پشتیبانی‌شده (`MEASUREMENT_SPECS`): وصول مطالبات، سود کالا، تعداد فروش، فروش مشتریان هدف،
نرخ هم‌خرید، میانگین فاکتور، نرخ ابطال، فروش روز اوج، اضافه‌پرداخت خرید، روزهای موجود بودن.
معیار ناشناس → `NOT_MEASURABLE` (با همان صراحت).

## ۵. بازیابی — چه چیزی و چقدر

`memory.retrieve(db, question, …)` فقط بخش مربوط را می‌آورد:

- آخرین پیام‌های مرتبط (حداکثر ۸) — نه کل تاریخچه.
- فکت‌های کسب‌وکار هم‌دامنه با سؤال.
- سیاست‌های مربوط به نوع تصمیم.
- تصمیم‌های مشابه گذشته + **پیامد واقعی‌شان**.

سؤال «جشنوارهٔ قبلی جواب داد؟» در مسیر واقعی:
`search_decisions` → تصمیم کمپین پیشین → `get_campaign_outcome` → عدد واقعی فروش/سود → پاسخ با ارجاع به `decision_id`.

**هرگز ارسال کل دیتابیس یا کل تاریخچه به پرامپت ممنوع است** — این در `prompts.build_context` و محدودیت ۴۰۹۶ توکن اعمال شده.

## ۶. تداوم گفت‌وگو («این کالا» → «۵ روز» → «اجراش کن»)

موجودیت‌های حل‌شده در پاسخ دستیار زیر `meta.entities` ذخیره می‌شوند
(`product_id`, `product_name`, `customer_id`, `supplier_id`, `percent`, `days`).
`planner._needs_prior` برای ارجاع‌های مبهم («همون»، «اجراش کن»، «۵ روز») آن‌ها را برمی‌گرداند
و تصمیم قبلی ادامه پیدا می‌کند — تست‌شده در `tests/test_v40_brain.py`.

---

## ۷. تضادها — هرگز بازنویسی بی‌صدا

اگر حافظهٔ کسب‌وکار با واقعیت جدید تضاد داشته باشد (مثلاً مدیر می‌گوید «تأمین‌کنندهٔ Y ارزان‌تر است»
اما تاریخ خرید خلافش را نشان می‌دهد)، تضاد **ثبت** می‌شود و به مدیر نشان داده می‌شود؛
مقدار قبلی بی‌صدا پاک نمی‌شود (قاعدهٔ «never silent overwrite»).

بررسی‌های تضاد موجود (`contradictions`):
`BUY_WITHOUT_CASH`, `DISCOUNT_WHILE_DEMAND_LOW`, `DISCOUNT_BELOW_MARGIN`,
`LEAD_TIME_LONGER_THAN_STOCK`, `DATA_QUALITY`, `MARGIN_AND_CASH`.
