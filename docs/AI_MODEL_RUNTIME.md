# AI MODEL RUNTIME (v4.0)

**هدف:** اجرای یک مدل زبانی کوچک **روی همان دستگاهی که فروشگاه با آن کار می‌کند** — بدون وابستگی سنگین پایتون، بدون اینترنت اجباری، با سقف حجم ۲ گیگابایت.

---

## ۱. اینترفیس `AIProvider` (`runtime.py`)

هر ارائه‌دهنده دقیقاً این قرارداد را دارد:

```python
class AIProvider:
    name: str
    def load(self) -> bool          # آماده‌سازی موتور/اتصال
    def unload(self) -> None        # آزادسازی حافظه
    def chat(self, messages, **kw) -> str
    def generate(self, prompt, **kw) -> str
    def structured_output(self, schema, messages, **kw) -> dict
    def tool_call(self, messages, tools, **kw) -> dict   # {"name":…, "arguments":{…}}
    def health_check(self) -> dict  # {"ok":bool, "detail":…}
    def benchmark(self) -> dict     # {"tokens_per_second":…, "ms":…}
```

سه پیاده‌سازی:

| ارائه‌دهنده | شرط فعال‌شدن | کاربرد |
|---|---|---|
| `LlamaCppProvider` | وجود `llama-server` (یا باینری ثبت‌شده) | **پیش‌فرض، محلی** |
| `CloudProvider` | فقط اگر `ai_mode` اجازه دهد **و** کلید تنظیم شده باشد | اختیاری، هرگز اجباری |
| `TemplateProvider` | همیشه | مسیر قطعی، پاسخ بدون مدل |

`runtime.provider_status(db)` وضعیت واقعی را برمی‌گرداند (`deterministic` / `local` / `cloud`) و **پنهان نمی‌کند** که مدل نیست یا خطا داده.

### llama.cpp چگونه صدا زده می‌شود

- به‌صورت **زیرفرایند** (`llama-server`) روی پورت `DEFAULT_PORT = 8080`
  (قابل تغییر با سیاست `brain.runtime.port`)، یا اتصال به سروری که از قبل بالاست.
- درخواست HTTP به `/v1/chat/completions`.
- **هیچ وابستگی پایتونی سنگین لازم نیست**: نه `llama-cpp-python`، نه `torch`.
  روی ویندوز و لینوکس یک فایل اجرایی کافی است؛ روی اندروید JNI/سرویس بومی.

## ۳. حلقهٔ ابزار (`ToolLoop`) — حداکثر ۸ دور

```
دور ۱..۸:  مدل → tool_call → REGISTRY.call(ctx, name, args) → نتیجه → مدل
دور آخر:   ابزار خاموش است؛ مدل باید جواب بدهد
```

- `≤ MAX_TOOL_ROUNDS = 8` — حلقهٔ بی‌نهایت ممنوع.
- رد شدن ابزار (`ToolDenied`) به مدل به‌صورت `{"ok": false, "error": "TOOL_DENIED"}` برمی‌گردد، نه استثنا.
- اگر دور هشتم هم جواب نبود: پاسخ قطعی `planner_text` جایگزین می‌شود و `warnings=[MODEL_FAILED]` ثبت می‌شود.
- ابزارها همیشه از `REGISTRY.call` می‌گذرند یعنی مجوزها حتی در مسیر LLM هم اعمال می‌شود.

## ۴. بودجهٔ متن — «هرگز کل دیتابیس»

- الگوی پیش‌فرض: `chunks + pins` (`prompts.build_context`) — فقط آنچه بازیابی شده.
- تاریخچهٔ گفت‌وگو: **حداکثر ۸ پیام اخیر** و فقط بخش مربوط به سؤال (`memory.recent()`).
- `context_default = 4096` توکن. روی دستگاه ۴ گیگابایتی **۸۱۹۲ فعال نمی‌شود**.
- `device_profile.context_for(prof)` تصمیم می‌گیرد؛ حالت بزرگ فقط اگر بنچمارک واقعی اجازه دهد.

## ۵. وضعیت‌های آشکار (هیچ‌چیز پنهان نمی‌شود)

| وضعیت | معنی | نمایش |
|---|---|---|
| `binary_missing` | `llama-server` نصب نیست | «موتور محلی نصب نیست» + دستور نصب در `AI_MODEL_INSTALLATION.md` |
| `not_installed` | مدلی دانلود نشده | «مدلی نصب نشده — پاسخ‌ها قطعی است» |
| `unverified` | فایل هست ولی sha256 تأیید نشده | **بارگذاری نمی‌شود** |
| `failed` | بنچمارک رد شد | مدل فعال نمی‌شود، مورد قبلی برمی‌گردد |
| `degraded` | مدل خطا داد | پاسخ قطعی + هشدار |
